\section{1. Problem Definition \& Intended Use Case}
Visually impaired individuals encounter hazardous obstacles during daily mobility, including low-lying clutter, knee-to-waist hazards, and sudden vertical drops. Furthermore, accidental cane drops or user falls can leave individuals stranded without immediate assistance. Existing commercial Electronic Travel Aids (ETAs) present three critical shortcomings: (1) prohibitive acquisition costs often exceeding \$500 USD (LKR 150,000+), (2) architectural reliance on cloud connectivity for basic hazard detection, and (3) acoustic audio spam that obstructs natural hearing. 

\textbf{IntelliCane} addresses these issues directly. It provides an ultra-low-cost (LKR 2,800 bench electronics), 100\% offline-safe assistive white cane that pairs real-time haptic obstacle guidance and inertial fall detection with a dedicated companion Android mobile application for blind users and their caretakers.

% Section 2
\section{2. Proposed Solution \& System Overview}
The IntelliCane ecosystem integrates an intelligent embedded controller on the cane with a dual-mode companion smartphone application:
\begin{itemize}
    \item \textbf{Safety-Critical Cane Reflex (ESP32-C3):} Executes a sub-50\,ms deterministic loop. An HC-SR04 ultrasonic transceiver detects forward hazards up to 4 meters, driving a 3-pin vibration motor via 200\,Hz hardware LEDC PWM that scales smoothly between 60\,cm and 10\,cm. A 6-axis MPU6050 IMU detects orientation and impact forces ($>65^\circ$ tilt or $>2.5\,g$). Upon detecting a fall, the cane automatically enters a silent emergency state (disabling local buzzer and motor to avoid user distress) while immediately routing high-priority alert packets over BLE.
    \item \textbf{Companion Android Application (\texttt{com.example.intellicane}):} Connects wirelessly over Bluetooth Low Energy (BLE 5.0 Nordic UART Service). Operates in two dedicated modes:
    \begin{itemize}
        \item \textit{Blind User Dashboard:} Accessible interface with connection indicators, one-tap A-GPS location sharing, and a collapsible floating terminal window for on-demand telemetry diagnostics without visual clutter.
        \item \textit{Caretaker Mode:} Real-time presence tracking, automated emergency fall alerts synchronized directly via Firebase Firestore, and an interactive ESRI/OpenStreetMap (OSMDroid) interface with an instant user-centering FAB (18.5x zoom)---eliminating the cost, weight, and power draw of a standalone hardware GPS module.
    \end{itemize}
\end{itemize}

\section{4. Hardware Implementation \& Circuit Design}
The cane hardware is designed around the stamp-sized \textbf{ESP32-C3 SuperMini} powered by a regulated 5\,V rail:
\begin{itemize}
    \item \textbf{Ultrasonic Ranging (HC-SR04):} Triggered via 10\,$\mu$s pulses on GPIO 0. The Echo pulse is connected directly to GPIO 1, keeping the bench prototype wiring minimal, robust, and efficient.
    \item \textbf{Inertial Motion Sensor (GY-521 MPU6050):} Communicates over hardware I2C (SDA: GPIO 4, SCL: GPIO 5) at 100\,kHz. AD0 is grounded to set address \texttt{0x68}. A custom direct-register fallback driver ensures resilience against clone ICs and bus lockups.
    \item \textbf{Tactile Haptic Motor Module:} 3-pin vibration motor module with onboard MOSFET driver powered from 5\,V; gate modulated via GPIO 6 at 200\,Hz PWM, providing gradual spatial perception without hand numbness.
    \item \textbf{Audible Hazard Alarm:} Active/passive 3.3\,V buzzer on GPIO 7 provides urgent pulsed alerts for close obstacles ($<30$\,cm), while automatically silencing during fall events to prevent user panic.
\end{itemize}

% Section 5
\section{5. Firmware Architecture \& Control Logic}
The firmware (\texttt{firmware/core-sensing/core-sensing.ino}) operates with zero blocking \texttt{delay()} calls, utilizing a cooperative time-sliced scheduler:
\begin{itemize}
    \item \textbf{Task Rates:} Ultrasonic ranging @ 20\,Hz (50\,ms), IMU tilt tracking @ 50\,Hz (20\,ms), Actuator PWM updates @ 100\,Hz (10\,ms), and BLE telemetry transmission @ 10\,Hz (100\,ms).
    \item \textbf{Proportional Ramping Equation:} The PWM duty cycle ramps monotonically as obstacle distance $d$ decreases:
    $$\text{PWM Duty} = \text{constrain}\left(255 - \frac{d - d_{\min}}{d_{\max} - d_{\min}} \times (255 - \text{PWM}_{\min}),\ \text{PWM}_{\min},\ 255\right) \quad (d_{\min}=10\,\text{cm},\ d_{\max}=60\,\text{cm})$$
    \item \textbf{Silent Fall Detection \& BLE Dispatch:} Tilt $>65^\circ$ or impact acceleration $>2.5\,g$ triggers emergency fall mode. The cane silences local haptic and audible alerts, transitions the onboard LED, and immediately broadcasts \texttt{FALL\_STATE:1} and \texttt{[ALERT: FALL DETECTED!]} over BLE. Restoring the cane upright ($<30^\circ$) transmits \texttt{FALL\_STATE:0} and automatically restores normal navigation.
\end{itemize}

% Section 6
\section{6. Companion Mobile Application (\texttt{application/})}
The native Android application is structured in Kotlin (\texttt{com.example.intellicane}) to bridge IoT telemetry:
\begin{itemize}
    \item \textbf{BLE GATT Central Client:} Auto-discovers \texttt{Intelligent-Cane}, connects to Nordic UART Service, and parses telemetry: {\small\texttt{DIST:...|TILT:...|FALL:...|MOTOR:...|BUZZ:...|BLE:...}}.
    \item \textbf{User Dashboard \& Floating Terminal:} Blind users view simple high-contrast status and location-sharing controls. A collapsible floating terminal toggle (\texttt{btnToggleTerminal}) allows on-demand viewing of live sensor data without cluttering the screen.
    \item \textbf{Caretaker Map \& Emergency Centering:} Integrates \texttt{org.osmdroid} with ESRI tile sources. Features a dedicated FAB (\texttt{fabUserLocation}) to immediately center and zoom (18.5x) on the blind user's real-time A-GPS coordinates.
    \item \textbf{Firebase Cloud Backend:} Syncs state with Cloud Firestore and Realtime Database. Upon receiving \texttt{FALL\_STATE:1}, \texttt{updateFallStateInFirestore} immediately flags the emergency in the cloud to alert caretakers.
\end{itemize}

\section{7. Testing, Validation \& Verification Evidence}
\begin{itemize}
    \item \textbf{Host Unit Testing (\texttt{tests/proximity\_feedback\_test.cpp}):} 100\% pass across boundary conditions, invalid inputs (NaN, $\infty$, negative distances), monotonic PWM progression, motor polarity inversion, and 32-bit \texttt{millis()} rollover resilience.
    \item \textbf{Bench Distance Calibration:} HC-SR04 verified against physical tape measurements from 2\,cm to 250\,cm with $\pm 1.5$\,cm accuracy. Motor PWM engages deterministically at 59.9\,cm and hits 100\% duty at 10\,cm.
    \item \textbf{Tilt Verification:} Calibrated with a digital protractor; fall alarm triggers reliably at $>65^\circ$ and silences within 200\,ms of cane recovery ($<30^\circ$).
    \item \textbf{Wireless BLE Performance:} Telemetry stream validated at 10\,Hz to smartphone with $<25$\,ms latency and up to 10\,m range.
\end{itemize}

\section{9. Limitations, Risks \& Mitigations}
\begin{itemize}
    \item \textbf{Ultrasonic Specular Scattering:} Sound waves can scatter on angled soft fabrics beyond 2 meters. \textit{Mitigation:} For the final build, a Time-of-Flight (ToF) laser ranging sensor will be integrated as a complementary secondary channel.
    \item \textbf{Breadboard Jumper Durability:} Prototype jumpers can loosen under prolonged mechanical tapping. \textit{Mitigation:} Migrating to a custom two-layer PCB and vibration-isolated enclosure before the final competition.
    \item \textbf{Smartphone Disconnection:} If the phone battery depletes, remote caregiver tracking stops. \textit{Mitigation:} Core obstacle avoidance and local audio-visual fall alarms remain 100\% operational offline on the cane.
\end{itemize}
